# Fridge-to-Table — Product spec (demo, Oct 2026)

## 1. Background

- Part of an internal program, "50 Multimodal Agent Apps". Each idea gets a thin, working demo. A demo passes only if **a real person ran it on their own input and said they would use it again**. Demos that pass move on to a "deepening" phase: memory, continuity, a real user. The code is later released as open source.
- Company strategy: take app ideas proven in the West and bring them, with some added value, to markets where they do not exist yet. The full project will later add Chinese support and Huawei hardware. **None of that is in this demo.**
- Western precedents: FridgeSmart (inventory from photos, receipts and barcodes, meal plans, shopping lists), Samsung Family Hub (camera inside the fridge), Skylight Calendar (photo of the fridge → recipes and shopping list).
- Longer term, "what is where in this kitchen, right now" feeds a robotics interface layer (ATARI). That is context only, not demo scope.

## 2. The product in one sentence

A kitchen agent that knows what is in your home: photograph the fridge and pantry, then chat with it to get meals you can cook right now, or what you are missing for the dish you want. It remembers what your family likes and checks its own suggestions.

**Target user:** parents and working adults who cook at home regularly. The problem: "what do I cook tonight?" every day, forgotten food going bad, discovering a missing ingredient halfway through cooking.

## 3. Decisions (these override any older planning document)

| Topic | Decision |
|---|---|
| Language, cuisine | English only. General cuisine. |
| Team | One developer. |
| Usage modes | Mode A (what can I cook) and Mode B (I want to make X). Mode C (multi-day plan) is **out**. |
| Agent | A real agent: an LLM in a tool loop decides which tools to call. Deterministic code verifies. |
| Framework | Pydantic AI. No openJiuwen, no Ascend in the demo. |
| Models | Commercial APIs. Vision: Gemini 3.5 Flash. Agent: Claude Sonnet 5.5. Both swappable (see §9). |
| Recipes | Generated by the model, checked by code. No hand-written recipe database. |
| Inventory correction | Editable side panel with uncertain items highlighted. The agent also asks about up to 3 uncertain items in chat. No separate clarification wizard. |
| Staples | Default editable list (salt, oil, ...) assumed present unless the user removes them. |
| Expiry | No expiry tracking. The user marks items "use soon". |
| Persistence | Inventory and preferences persist across sessions. Chat history per session. |
| UI | Mobile web app: chat + inventory side panel (a drawer on a phone). |

## 4. Core flows

**Flow 1: build the inventory**
1. The user attaches 1–4 photos in the chat (fridge, freezer, pantry). They may write a message along with them, or nothing.
2. The agent calls `recognize_inventory`. Items appear in the side panel, uncertain ones highlighted at the top.
3. The agent sends a short summary ("Found 23 items. Two I'm not sure about: is the white container leftover rice? Is that yogurt or sour cream?").
4. The user answers in chat, or edits the panel directly (delete, rename, change quantity, toggle "use soon").

**Flow 2: Mode A, what can I cook**
1. The user writes something like "What can I cook tonight?" or "something quick, 30 min, kids are eating".
2. The agent may first update the inventory if the message says so ("we're out of eggs").
3. The agent calls `suggest_meals` with the constraints, then `validate_suggestion` on each candidate. It replaces candidates that fail.
4. The reply shows up to 3 meal cards: name, time, which inventory items it uses (with "use soon" items marked). Tapping a card opens the full recipe.

**Flow 3: Mode B, I want to make X**
1. "I want to make lasagna."
2. The agent calls `get_recipe("lasagna")`, then `compute_missing`.
3. For each missing essential ingredient, the agent checks whether something in the inventory is a reasonable substitute (e.g. cottage cheese for ricotta) and proposes it.
4. The reply shows the recipe card, the substitutions it proposes, and a shopping list of what is still missing.

**Flow 4: preferences (memory)**
- When the user states a lasting like or dislike ("the kids hated the eggplant", "we don't eat pork"), the agent calls `save_preference`.
- Stored preferences are injected into the agent's instructions on every run, and `validate_suggestion` rejects meals with an avoided ingredient.
- They persist across sessions. In a new session, suggestions respect them without being reminded.

**Flow 5: proactive opening**
- When the app opens and the inventory is not empty, the agent greets with a suggestion that targets "use soon" items ("Your spinach needs using. Want a spinach dish tonight?"). If no "use soon" items exist, it gives a short generic greeting with one quick idea.

**Stretch (only if the Oct 20 decision point passes):**
- "We cooked it": after the user confirms they cooked a suggested meal, the agent lowers the used ingredients (`plenty → some → low → removed`) via `update_inventory`.
- Share shopping list: a button that copies the list as plain text.

## 5. Agent behaviour

Instructions the agent must follow (encode them in the agent's instructions):

- Never claim an item is in the inventory without having read it via a tool in this run (`get_inventory`) or in the injected inventory summary.
- Before presenting any meal, it must pass `validate_suggestion`. If it fails, fix it: swap the meal, use a substitute from the inventory, or present it as a Mode B result with a shopping list.
- Prefer meals that use "use soon" items.
- Respect stored preferences. When the user states a lasting preference, save it.
- When the inventory has uncertain items, ask about at most 3, in one message.
- Keep replies short. Meals go in structured cards, not prose.
- Never order, buy or delete anything on the user's behalf without an explicit request.
- At most ~8 tool calls per turn. If stuck, answer with what it has.

## 6. Tools (contracts)

All tools live in `app/tools/` as plain functions with Pydantic I/O. The agent wraps them.

| Tool | Kind | Input → Output |
|---|---|---|
| `recognize_inventory(image_paths)` | LLM (vision) | images → `list[InventoryItem]` (draft, with `confidence`, `uncertain`) |
| `get_inventory()` | code | → `list[InventoryItem]` (confirmed + staples) |
| `update_inventory(changes)` | code | `list[InventoryChange]` (add / remove / set_qty / set_use_soon / rename) → updated inventory |
| `suggest_meals(constraints, n, exclude)` | LLM (text) | free-text constraints, how many, dishes to exclude → `list[Recipe]` candidates (structured) |
| `get_recipe(dish)` | LLM (text) | dish name → `Recipe` |
| `compute_missing(recipe)` | **code** | `Recipe` → `MissingReport` (essential ingredients missing, after normalization and staples) |
| `validate_suggestion(recipe)` | **code** | `Recipe` → `ValidationResult` (ok, missing essentials, violated preferences) |
| `save_preference(text, avoid)` | code | free text + list of canonical ingredients to avoid → `Preference` |
| `get_preferences()` | code | → `list[Preference]` |

Notes:
- `suggest_meals` and `get_recipe` receive the current inventory and preferences inside their prompt, and must return structured `Recipe` objects. Their output is never trusted: `validate_suggestion` / `compute_missing` decide.
- Substitutions in Mode B are proposed by the agent itself (it has the inventory). The output validator checks that every proposed substitute is in the inventory.

## 7. Data model

```python
QtyLevel = Literal["plenty", "some", "low"]
Location = Literal["fridge", "freezer", "pantry"]

class InventoryItem(BaseModel):
    id: str
    name: str               # canonical, from normalize()
    display_name: str       # what the user sees, e.g. "Greek yogurt"
    category: str           # vegetable, fruit, meat, fish, dairy, egg, grain, sauce, condiment, spice, drink, other
    qty_level: QtyLevel
    location: Location
    confidence: float       # 0..1, from recognition; 1.0 for manual
    uncertain: bool         # confidence below threshold, or flagged by the model
    use_soon: bool = False
    is_staple: bool = False
    source: Literal["photo", "chat", "manual", "staple"]
    updated_at: datetime

class Ingredient(BaseModel):
    name: str               # canonical
    amount: str             # free text, "300 g", "2", "a handful"
    essential: bool

class Recipe(BaseModel):
    name: str
    ingredients: list[Ingredient]
    steps: list[str]
    time_minutes: int
    servings: int = 4
    uses_from_inventory: list[str] = []   # canonical names, filled by code, not by the model

class Preference(BaseModel):
    id: str
    text: str               # "kids dislike eggplant"
    avoid: list[str]        # canonical ingredients
    created_at: datetime

class MissingReport(BaseModel):
    missing_essential: list[str]
    missing_optional: list[str]

class ValidationResult(BaseModel):
    ok: bool
    missing_essential: list[str]
    violated_preferences: list[str]

class Substitution(BaseModel):
    missing: str
    use_instead: str        # must be in the inventory (checked)

class ToolTraceItem(BaseModel):
    tool: str
    args_summary: str
    result_summary: str

class AgentReply(BaseModel):
    message: str                         # short text
    meals: list[Recipe] = []             # Mode A cards (max 3) or the Mode B recipe
    substitutions: list[Substitution] = []
    shopping_list: list[str] = []
    questions: list[str] = []            # clarifying questions about uncertain items (max 3)
    # trace is attached by the server from the run's messages, not produced by the model
```

**Matching rule (used by `compute_missing` and `validate_suggestion`):** an ingredient counts as available if its canonical name equals an inventory item's canonical name, or both map to the same entry in `data/synonyms.json`, or it is in the staples list (and the user has not removed that staple). Items with `qty_level == "low"` still count as available. Optional ingredients never fail validation.

## 8. UI

One page, mobile first.
- **Chat** (main area): message bubbles; an attach-photo button (camera or gallery, up to 4); text input.
- **Meal cards** inside agent messages: name, time, the inventory items it uses (chips; "use soon" chips highlighted). Tap → full recipe in a bottom sheet.
- **Shopping list** block inside agent messages when present, with substitutions shown above it.
- **Trace line** under each agent message, collapsed by default: "3 tools · updated inventory → 5 candidates → 1 failed (no cream) → replaced". Expanded: one line per tool call.
- **Inventory panel**: a drawer opened from a header button, with a count badge. Grouped by location. Uncertain items at the top with a warning style. Each item: name, quantity level (tap to cycle), "use soon" toggle, delete. "Add item" input. A "Staples" section that can be collapsed.
- Loading state while the agent runs. If possible, stream the message text.

## 9. Model choice

Based on Roboflow Vision Evals (Oct 8, 2026): five tasks, scored against ground truth. The task here needs **identification** (what is this item), **counting** (rough quantities) and **OCR** (labels on jars and packages). Bounding boxes are not needed.

| Model | Overall | Identification | Counting | OCR | Cost / sample | Speed |
|---|---|---|---|---|---|---|
| GPT-6 Astra | 83.4% | 89.6 | 80.2 | 77.8 | $0.034 | 9.9 s |
| Claude Opus 5.5 | 82.0% | 93.8 | 80.6 | 78.3 | $0.015 | 7.6 s |
| **Gemini 3.5 Flash** | 81.8% | **99.0** | 80.6 | 76.7 | $0.012 | 11.5 s |
| Qwen3.8 Max | 79.3% | 88.5 | 81.1 | 74.0 | $0.008 | 19.0 s |
| Claude Sonnet 5.5 | 77.6% | 91.7 | 79.3 | 66.3 | $0.0073 | 8.3 s |

Source: https://playground.roboflow.com/evals

- **Vision default: Gemini 3.5 Flash.** Best identification score, near the top on counting and OCR, lower cost than the other top models.
- **Vision challenger (Oct 20 comparison): Claude Opus 5.5**, faster and best on OCR. Optional third: Qwen3.8 Max, as an early signal for the later Chinese/Ascend version.
- **Agent model default: Claude Sonnet 5.5**, for reliable tool calling and fast turns. Everything is behind env vars, so the agent model can be swapped too.
- Public benchmarks are a starting point. **The decision is made on our own fridge photos** (`eval/`), on Oct 20.

## 10. Acceptance criteria (demo is ready when all hold)

- [ ] ≥ 70% of visible items correctly identified before correction, on the eval set.
- [ ] ≤ 2 hallucinated items per photo on average.
- [ ] Every meal shown to the user passed `validate_suggestion` (enforced by the output validator).
- [ ] At least once in the demo, the trace shows the agent fixing a failed suggestion.
- [ ] "We're out of eggs, something in 30 minutes" updates the inventory, then suggests meals that need no eggs and take ≤ 30 min.
- [ ] A preference stated in one session changes suggestions in a new session.
- [ ] Mode B returns only what is truly missing, and proposes a substitute when one is in the inventory.
- [ ] Photo upload → inventory in panel: < 30 s. Meal request → reply: < 25 s.
- [ ] Inventory and preferences survive a server restart.
- [ ] The real user runs the full flow and says they would use it again.

(The numeric targets are first guesses. Calibrate them on Oct 20.)

## 11. Out of scope

Mode C (multi-day plans), structured family profiles, Chinese language and dishes, expiry estimation, receipts, delivery-app export or ordering, voice, video, live cooking guidance, multi-agent setups, auth or multiple households, Ascend, openJiuwen, native mobile apps.

## 12. Demo script (about 5 minutes, Oct 23)

1. Open the app on a phone. The proactive greeting suggests something with the "use soon" spinach (set up beforehand).
2. Photograph a real fridge (2 photos) and pantry (1). The panel fills with about 25 items. The agent asks about 2 uncertain ones. Answer in chat.
3. "What can I cook tonight? Something under 30 minutes, the kids are eating." Three cards. Open the trace: one candidate failed validation and was replaced.
4. "The kids hated the eggplant last time." The agent saves the preference.
5. "I want to make lasagna." Recipe, one substitution from the inventory, a shopping list of 3 items.
6. Reload the app (new session) and ask for dinner ideas. No eggplant. Point out that it remembered.
